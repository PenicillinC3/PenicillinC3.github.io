这篇教三件事：**改**已有的网页、**删**不要的网页、**清**掉冗余内容。适合完全没碰过命令行的新手 —— 每步都给完整命令，复制粘贴就能跑。写**新**内容的流程见《本站内容写作与发布教程》。

先说三句大白话背景，懂了就不慌：

- 网站上的每篇内容 = `src/content/` 文件夹里的一个普通文本文件（`.md` 后缀）。**改网站就是改这些文本文件**。
- 网页上的列表、导航是程序根据文件夹里现存的文件**自动生成**的 —— 所以增删文件后，列表会自动跟着变，**不用手动改任何"列表"**。
- 发布要过两道闸：`npm run build`（本地体检，红灯就不让过）→ `git push`（上传，等约 2 分钟自动上线）。第一步体检没过就绝不上传，所以随便改、改错了也伤不到线上。

## 第 1 步：找到「我要改的网页」是哪个文件

**网址的最后一段 = 文件名**（网址没有文件名后缀）：

| 你看到的网址                    | 要打开的文件                                 |
| ------------------------------- | -------------------------------------------- |
| `/notes/git-rebase-cheatsheet/` | `src/content/notes/git-rebase-cheatsheet.md` |
| `/musings/slow-photography/`    | `src/content/musings/slow-photography.md`    |
| `/links/plaintext-blog/`        | `src/content/links/plaintext-blog.md`        |
| `/projects/photo-organizer/`    | `src/content/projects/photo-organizer.md`    |
| `/photos/nikon-roll/`           | 见下文「照片和胶卷」                         |

在电脑上打开项目文件夹 `D:\_Vibe`，按这个路径一层层点进去（`src` → `content` → 对应栏目名），就能看到所有内容文件。**没有记事本以外的编辑器也能改**，但推荐装一个 VS Code，改坏了能 `Ctrl+Z` 撤销。

## 第 2 步：改内容

用记事本或 VS Code 打开 `.md` 文件，你会看到：

```yaml
---
title: 网页大标题
date: 2026-09-01
summary: 列表卡片上显示的那句话
tags: [CSS, 工具]
---
正文从这里开始，想写什么写什么。
```

- 最上面两个 `---` 之间的叫 **frontmatter**（元信息），改它 = 改标题/日期/卡片摘要/标签。比如想改网页顶部的大标题，就改 `title:` 后面引号里的字。
- `---` 下面的都是**正文**，像写文章一样随便改。段落之间要空一行，想删哪段就删掉哪段。
- 改完**必须保存**（记事本 `Ctrl+S`），然后回到项目根目录 `D:\_Vibe` 的终端窗口，依次执行：

```bash
npm run build
git add -A
git commit -m "更新笔记：改了什么说一句"
git push
```

**每一步你应该看到什么：**

- `npm run build` 结尾出现 `16 page(s) built`（数字会变）且没有红色 `error` —— 体检通过。如果报红字，它会在红字里**点名是哪个文件**（如 `src/content/notes/xxx.md`），照着红字提示改即可，常见的三种原因见文末速查表。
- `git commit` 后出现一长串字母数字 —— 本地存好档了。
- `git push` 后出现 `main -> main` —— 上传成功，约 2 分钟后刷新网页就能看到改动。

想先看效果再发布？终端里先跑 `npm run dev`，浏览器打开 `http://localhost:4321` —— 这是**本地预览**，只有你能看到，改文件会实时刷新，满意了再按上面四行发布。

## 第 3 步：删除一整篇网页

**推荐先试"软删除"（反悔零成本）**：在文件 frontmatter 里加一行 `draft: true`，保存后照常 build + push。效果 = 网页立即从网站消失（本地预览仍能看到），但文件还在 —— 想恢复就把这行删掉再推一次。适用于"还没想好要不要删"。

**确认不要了，真删**：直接在文件管理器里把那个 `.md` 删掉（或右键删除），然后：

```bash
npm run build
git add -A
git commit -m "删除笔记：xxx"
git push
```

- build 不报错 = 删干净了；原网址从此返回 404（打不开），这是**正常现象**，就像报纸上撕掉了一页。
- 别人收藏夹/搜索引擎里可能还留着旧链接，点开是 404 —— 无害，不用管。
- 推送之后才反悔？文件在回收站就直接还原；回收站也清了就找 Claude Code：「帮我把 xxx 从 git 历史里恢复」—— 本站每次发布都有存档，基本都能找回。

## 第 4 步：删除照片和整个胶卷（最容易踩坑的一步）

照片的规矩：**一张照片 = 两个文件配对**（同名），比如 `harbor-sunset.md` 和 `harbor-sunset.jpg` 放在 `src/content/photos/<所属卷>/` 文件夹里（照片按卷分文件夹存放）。删的时候**两个都要删** —— 只删一个，build 会报错提示找不到图片。

删照片前**先查一件事**：这张照片是不是某卷的封面。打开 `src/content/series/` 文件夹里的每个 `.md`，看有没有一行 `cover: <卷名>/harbor-sunset` 指着它（编号带卷名前缀）。有的话，要么先改那行换成别的照片 slug，要么连同整卷一起删 —— 否则封面指向不存在的照片，build 会报错。

**想删掉一整卷**（比如不再需要的示例卷）：一个卷 = `src/content/series/<卷名>.md`（卷的介绍页文字）+ 卷里所有照片的 `.md` 和图片文件。怎么知道卷里有谁？打开卷的 `.md`，卷内的照片文件里都有一行 `series: <卷名>` 挂着它。**一次性全部删光**（卷文件 + 每张照片的两个文件），然后照常：

```bash
npm run build
git add -A
git commit -m "删除摄影卷：xxx"
git push
```

如果删完 build 报错说卷空了/照片找不到 —— 说明有一侧没删干净（卷文件还在但照片没了，或反过来），去补齐即可。照片删了但**没挂任何卷**、或者卷删了但照片还留着：照片文件不会出现在网站上（只占硬盘），想彻底清掉就把配对的两个文件也删了。

## 第 5 步：清理冗余内容（什么能删、什么千万别动）

| 内容                                                                    | 处置                                                                        |
| ----------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 旧草稿、不再需要的页面                                                  | 删文件（或加 `draft: true` 藏起来）                                         |
| 示例照片/示例卷                                                         | 可删，方法见第 4 步                                                         |
| 每个栏目里的 `_xxx-template.md.example` 模板                            | **别删** —— 以后开新篇靠复制它                                              |
| `src/pages/` 里的文件                                                   | **别碰** —— 列表页/详情页是程序，删了网站结构就坏了                         |
| `node_modules/`、`dist/`、`.astro/` 文件夹                              | **别手动删** —— 构建时自动生成                                              |
| 根目录 `img/` 文件夹（原始大照片）                                      | **别删** —— 不进 git，删了无法从历史找回，等于丢原片                        |
| 根目录 `font/` 文件夹（字体原件，`STZHONGS.TTF`、`MapleMono-*.ttf` 等） | **别删** —— `npm run fonts:subset` 靠它们重建网站字体，删了该命令会直接报错 |
| `public/fonts/` 里的字体子集                                            | 别手动删单个 —— 需要更新就跑 `npm run fonts:subset` 自动重建                |

一条内容"还在不在网站上"，以 `npm run dev` 的本地预览（或线上网址）为准，别凭文件夹判断 —— 有些文件（没挂卷的照片）本来就只在硬盘上、不上网站。

## 文末速查

**一条完整流程**（改 / 加 / 删通用）：

```bash
npm run build      # 体检：看有没有红色 error
npm run fonts:subset   # 只在新内容用了生僻汉字时跑，其他情况跳过也行
git add -A         # 把所有改动装进待提交
git commit -m "做什么了：一句话"
git push           # 上传发布，约 2 分钟生效
```

**build 报错怎么看**（报错名字一定是某个 `.md` 文件，别慌）：

| 红字长这样（节选）      | 大白话             | 处理                                  |
| ----------------------- | ------------------ | ------------------------------------- |
| `date 需为 YYYY-MM-DD`  | 日期格式写错了     | 改成 `2026-09-01` 这种，别加引号      |
| `alt 必填`              | 照片说明缺一行     | 在照片 `.md` 里补 `alt: 描述图片内容` |
| `找不到图片 / image …`  | 图没了或名字对不上 | 检查照片是否和 `.md` 同名同文件夹     |
| 提到 `series` / `cover` | 删照片时误伤卷封面 | 按第 4 步检查 `series/` 里的 `cover:` |

**最后一句最重要的**：build 不报错才会上线，所以随便折腾，改坏了 build 会拦住你，不会把坏页面发出去。卡在任何一步，把终端里的红字整段发给 Claude Code 就行。
